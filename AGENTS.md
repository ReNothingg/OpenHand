# OpenHand / «Чернильник»

## Что это

Клиентское React-приложение для подготовки рукописных конспектов и отправки однолинейных траекторий на перьевой плоттер. Интерфейс поддерживает Markdown, ограниченный TeX, обычные экранные шрифты и специальные однолинейные `.gfont`.

Проект работает без собственного сервера и без HTTP API. Данные документа, настройки и пресеты сохраняются в `localStorage`. Подключение к устройству выполняется напрямую из Chromium через Web Serial.

## Основные команды

- `npm run dev` — Vite-сервер разработки.
- `npm run build` — обязательная проверка production-сборки.
- `npm run preview` — локальный просмотр собранного `dist`.

## Главные потоки данных

1. `src/App.jsx` хранит документ и настройки, выбирает Markdown или TeX.
2. `src/markdown.js` / `src/tex.js` превращают исходник в безопасный HTML.
3. `src/hooks/useRenderedPages.js` раскладывает HTML по физическим страницам.
4. Обычный режим показывает HTML в `src/components/preview/PreviewPanel.jsx`.
5. Режим плоттера:
   - `src/plotter/richText.js` извлекает текст, формулы, оформление и SVG;
   - `src/plotter/job.js` раскладывает GFont-глифы и векторные линии в миллиметрах;
   - `src/hooks/useIntegratedPlotter.js` собирает листы и команды;
   - `src/hooks/usePlotter.js` работает с Web Serial;
   - `src/components/plotter/PlotterPaper.jsx` рисует точный SVG-предпросмотр траекторий.

## Важные каталоги

- `src/components/editor` — основной и расширенный редакторы.
- `src/components/settings` — настройки документа, шрифтов и плоттера.
- `src/components/preview` — страницы и toolbar предпросмотра.
- `src/components/plotter` — статистика, запуск и ручное управление.
- `src/plotter` — GFont, формулы, геометрия и генерация команд.
- `src/font` — локальные файлы обычных шрифтов.
- `src/gfonts` — встроенные однолинейные шрифты.
- `src/styles` — стили по областям интерфейса.

## Правила изменений

- Не загружать шрифты или рабочие данные с внешних серверов.
- Не использовать градиенты.
- Не возвращать отдельное модальное окно плоттера: управление встроено в основной интерфейс.
- Не дублировать одинаковый статус или метаданные в нескольких панелях.
- Экранный HTML и траектории плоттера должны одинаково понимать переносы, списки, формулы, выравнивание и заметки.
- Любой пользовательский HTML/SVG очищать через DOMPurify.
- Не отправлять на устройство обрезанный остаток страницы; предупреждение должно оставаться заметным.
- После UI-изменений запускать `npm run build` и проверять обычный/GFont-режимы в браузере.

## Среда и ограничения

- Web Serial доступен в Chrome/Edge на `localhost` или HTTPS.
- GFont — однолинейная геометрия, а не обычный TTF/OTF.
- SVG для плоттера преобразуется в полилинии; текст внутри SVG заранее должен быть переведён в контуры, если его необходимо начертить как часть изображения.
- Никаких backend-эндпоинтов сейчас нет. Если они появятся, документировать URL, метод, схему и место вызова в этом файле.
